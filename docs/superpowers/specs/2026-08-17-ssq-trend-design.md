# 双色球走势图网站 — 设计文档

日期：2026-08-17
状态：已确认

## 1. 背景与目标

原仓库（Go + Gin + SQLite，2015 年前后编写）代码已无参考价值，整体删除重建。
为彩迷家人重建一个**移动端优先**的双色球走势图工具：

1. 展示双色球开奖走势图（标准 33 红 + 16 蓝布局）
2. 用户在手机上通过**复选框滑动刷选**选中若干期，实时统计这些期中各数字的出现次数、冷热、遗漏、比例
3. 定时从福彩官网抓取最新开奖结果，存本地库；页面展示始终读本地库

## 2. 范围

### 做
- 双色球（SSQ）走势图 + 圈选统计 + 定时抓取
- 移动端优先（手机浏览器），同时兼容桌面浏览器

### 不做（YAGNI）
- 大乐透等其它彩种（表结构预留扩展空间，但本期不实现）
- 登录/多用户、走势连线、双指缩放、PWA 离线
- Cloudflare Serverless（已评估，本期选境外服务器自托管）

## 3. 总体架构

境外服务器自托管，一个 Go 二进制完成全部服务端职责：

```
                    ┌──────────────────────────────────────┐
                    │  境外服务器                           │
                    │                                      │
  每天 21:30(北京)   │  ┌──────────┐    upsert   ┌────────┐ │
  ┌───────────────  │  │ Go 定时任务│ ─────────→ │ SQLite │ │
  │  福彩官网接口     │  │ 抓取+解析  │             │  数据   │ │
  │  (cwl.gov.cn)   │  └──────────┘             └────────┘ │
  └───────────────  │        │                        │    │
                    │        ▼                        ▼    │
                    │  ┌─────────────────────────────────┐ │
                    │  │  Gin HTTP 服务                    │ │
                    │  │  /api/draws (走势图数据)          │ │
                    │  │  /static/* (React 构建产物)       │ │
                    │  └─────────────────────────────────┘ │
                    └──────────────────────────────────────┘
                                       ▲
                             手机浏览器（国内用户）
                        React 走势图 + 复选框刷选 + 统计面板
```

- 前端：React + Vite + TypeScript，构建产物由 Go 服务托管
- 后端：Go + Gin + SQLite，单二进制部署
- 域名：沿用 `lottery.nzai.me`，HTTPS 由 Nginx/Caddy 反代

## 4. 服务端设计

### 4.1 数据抓取

**数据源**：福彩官网公开接口
```
GET https://www.cwl.gov.cn/cwl_admin/front/cwlkj/search/kjxx/findDrawNotice
    ?name=ssq&pageNo={N}&pageSize=100&systemType=PC
```
返回 JSON，含期号、开奖日期、红球/蓝球号码。社区多个开源项目验证可用。

**首次启动：全量回填**
- 分页拉取全部历史（2003 年至今约 3500 期，约 35 页），写入 SQLite
- 抓取纪律：设置 User-Agent；每页间隔 1~2 秒；失败指数退避重试（最多 5 次）；超时 30 秒
- 回填在启动时异步执行（不阻塞服务启动），日志记录进度

**每日增量**
- 定时任务每天 21:30（北京时间）触发（双色球周二/四/日 21:15 开奖，每天抓一次覆盖所有开奖日）
- 拉取最新 1~2 页，检出比库中最新时期号更新的期，写入
- **幂等 upsert**（期号唯一），重复抓取无害
- 非开奖日抓取无新增，属正常，记一条日志即可
- 抓取失败不崩服务，仅记录日志，次日自动重试

### 4.2 数据模型

SQLite 单表：

```sql
CREATE TABLE draws (
    issue   TEXT PRIMARY KEY,   -- 期号，如 "2026087"
    date    TEXT NOT NULL,      -- 开奖日期 YYYY-MM-DD
    red1..red6  INTEGER NOT NULL, -- 6 个红球（升序存储）
    blue    INTEGER NOT NULL    -- 蓝球
);
```

数据量约 3500 行，SQLite 单文件零维护。

### 4.3 API

只读接口，统计全部由前端本地计算：

| 接口 | 说明 |
|---|---|
| `GET /api/draws?limit=100&before={issue}` | 走势图数据，JSON 数组，按期号倒序（最新在前）。`limit` 默认 100，最大 500；`before` 可选，用于分页取更早数据 |
| `GET /api/health` | 健康检查 |

响应格式（draws 数组元素）：
```json
{ "issue": "2026087", "date": "2026-08-13", "red": [4, 9, 17, 22, 28, 31], "blue": 7 }
```

### 4.4 静态托管与部署

- Gin 同时托管 `static/` 目录（React 构建产物，含 `index.html` 及 SPA 路由回退）
- 部署：Go 交叉编译 Linux amd64 二进制 + `static/` 目录上传服务器
- systemd 服务守护（`Restart=always`），Nginx/Caddy 反代 443 → Go 端口，配 `lottery.nzai.me` 证书
- 配置项（INI 或环境变量）：抓取开关、定时时间、UA、监听端口

## 5. 前端设计

### 5.1 技术栈

React 18 + Vite + TypeScript，无重型 UI 库（走势图与刷选交互自研，CSS 手写）。状态用 React 内置状态（useState/useReducer），不需要 Redux 等额外状态库。

### 5.2 页面布局（移动端优先）

```
┌────────────────────────────────────┐
│ 双色球走势图    [20][50][100][200][500] │  ← 顶部：标题 + 期数范围切换（默认 100）
├──────┬─────────────────────────────┤
│ ☑ 期号 │ 红球 1..33      蓝球 1..16    │  ← 表头
│ 日期  │（横向滚动）                    │
├──────┼─────────────────────────────┤
│ ☐ 2026087 │ ■ ■ ■ ■ ■ ■    ■      │  ← 每期一行
│ 08-13    │ 红球色块             蓝球色块 │
│ ☐ 2026086 │                        │
│ ...     │ （纵向滚动，可加载更早数据）   │
└──────┴─────────────────────────────┘
┌────────────────────────────────────┐
│ 已选 12 期    [清除选择]              │  ← 底部浮动栏（选中时出现）
└────────────────────────────────────┘
```

- **左侧固定列**（不随横向滚动移动）：复选框（约 44px 宽，触控友好）+ 期号 + 日期
- **中间区域**：33 列红球 + 16 列蓝球，横向滚动；纵向整体滚动，滚动到底自动加载更早数据（`before` 分页）
- 单元格：该期开出该号码 → 红/蓝色块；未开出 → 空白
- 顶部期数范围：20 / 50 / 100 / 200 / 500，切换即重新拉取并重置选择

### 5.3 圈选交互（复选框滑动刷选）

**核心原则：滚动与选择在空间上分流，互不干扰。**

- 复选框列内**手指滑动 = 刷选**：手指从某个复选框开始划过，经过的复选框被勾选；若起点复选框已是勾选态，则划过反向取消（标准刷选逻辑）
- 数字区域滑动 = 正常页面滚动（含横向滚动）
- 桌面端：点击复选框勾选，按住拖拽同样刷选
- 顶部"清除选择"按钮，随时重置

**实现要点**：
- 用 Pointer Events 统一鼠标/触屏
- 复选框列容器捕获 pointer 事件后 `setPointerCapture`，在 `pointermove` 中通过 `document.elementFromPoint` 或几何命中判断划过的行，更新选择集合
- 复选框列设 `touch-action: none`：该列固定且不参与任何滚动，触摸完全由 JS 接管用于刷选；页面纵向滚动从数字区域发起（数字区域保持默认 touch-action，支持 pan-x / pan-y）
- 追加加载更早数据（滚动到底分页）**不影响当前选择**；仅切换期数范围时重置选择

### 5.4 实时统计（debounce 300ms）

**性能结论**：统计计算为 O(N) 遍历，最多 500 期 × 7 数字 = 3500 个数据点，全部统计 < 1ms，无性能瓶颈。真正的渲染节奏控制如下：

- **刷选过程中**：仅更新选中行的高亮（CSS 类切换）和底部"已选 N 期"计数，不重算统计面板
- **刷选停顿 ≥300ms 或松手时**：计算统计结果，淡入渲染统计面板（`useMemo` 依赖选中集合，避免无效重算）
- 选中 0 期时隐藏底部栏和统计面板

**统计内容**（选中 N 期）：
1. **出现次数**：红球 1-33、蓝球 1-16 各自出现次数，降序排列，附出现率（出现次数 / N）
2. **冷热号**：按出现次数分档——热（> 均值）、温（≈ 均值）、冷（< 均值），均值 = 红球 6N/33、蓝球 N/16
3. **遗漏值**：每个数字距选中范围内最后一期（期号最大者）的未出现期数
4. **比例**：红球奇偶比、大小比（1-16 小 / 17-33 大）、蓝球奇偶

统计逻辑抽成纯函数模块（`src/lib/stats.ts`），输入 draws 数组 + 选中期号集合，输出统计结果——便于单元测试。

### 5.5 数据流

1. 页面加载 → `GET /api/draws?limit=100` → 渲染走势图
2. 滚动到底 → `GET /api/draws?limit=100&before=最早期号` → 追加渲染
3. 切换期数范围 → 重新拉取并重置
4. 刷选 → 选中集合变化 →（debounce）→ 纯函数统计 → 渲染面板

## 6. 错误处理与容错

| 场景 | 处理 |
|---|---|
| 官网接口抓取失败/超时 | 指数退避重试 5 次；仍失败记日志，服务不崩，次日重试 |
| 官网接口返回格式异常 | 单条数据校验（红球 6 个 1-33、蓝球 1-16、期号/日期非空），非法条目跳过并记日志 |
| 接口对境外 IP 限流/封禁 | 降低抓取频率配置项；提供手动抓取命令（`-sync` 参数触发一次） |
| 前端 API 请求失败 | 显示错误提示 + 重试按钮 |
| 首次回填未完成 | 服务照常启动，`/api/draws` 返回已入库数据，回填在后台继续 |

## 7. 测试策略

- **Go**：抓取解析单测（用官方接口真实返回 JSON 做 fixture）、`/api/draws` 集成测试（临时 SQLite）
- **前端**：Vitest 覆盖统计纯函数（出现次数/遗漏/奇偶大小比/冷热分档，含边界用例）、刷选逻辑（模拟 pointer 事件序列）
- **端到端**：本地起服务 + 手机浏览器实测刷选手感与滚动；部署后观察定时任务日志确认落库

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 官网接口变更/反爬升级 | 解析逻辑单点封装；每日日志监控抓取结果；提供手动同步命令 |
| 境外服务器访问官网接口慢/被限流 | 抓取频率可配置、退避重试；必要时换数据源（第三方开源镜像） |
| 手机端刷选手感不佳 | 复选框列宽 44px、`touch-action` 正确配置、pointer capture 命中优化；端到端实测调优 |
